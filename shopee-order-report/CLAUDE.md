# Shopee Order Report: บันทึกส่งต่องาน

Claude Code จะอ่านไฟล์นี้อัตโนมัติเมื่อเริ่ม session ในโฟลเดอร์นี้ (เช่นตอนรัน `claude remote-control`)

## เป้าหมายของเจ้าของงาน

เครื่องมือสรุปการซื้อของใน Shopee (shopee.co.th) ของตัวเอง มีหน้าที่ดังนี้

- แสดงรายการของที่ซื้อ **แยกตามเดือน** พร้อมยอดรวมของแต่ละเดือน
- รวมออเดอร์ที่ **จ่ายพร้อมกัน** (checkout เดียวกัน แม้จะมาจากหลายร้าน) ไว้เป็นกลุ่มเดียว
- บอกว่า **จ่ายด้วยอะไร** และถ้าจ่ายด้วยบัตร ให้บอกว่าเป็น **บัตรใบไหน** (Shopee แสดงแค่ 4 หลักท้าย เช่น `VISA *1234` ไม่มีเลขเต็ม)
- ใช้ง่าย: login ที่ https://shopee.co.th/ เองใน Chrome แล้วกดบุ๊กมาร์กปุ่มเดียว
- **ไม่นับ** ออเดอร์ที่ยกเลิกหรือยังไม่ชำระ

## ปัญหาที่ยังค้าง: ทำงานนี้ต่อ

ผู้ใช้ลองกับบัญชีจริงแล้วเจอปัญหาดังนี้

1. ได้รายการน้อยกว่าที่มีจริง
2. มีออเดอร์ที่ยกเลิกติดมาในรายงาน
3. สินค้าในออเดอร์ไม่ครบ

เวอร์ชัน 2 (commit `e11b2bb`) แก้สาเหตุที่ตรวจเจอจากการอ่านโค้ดไปแล้ว ดูรายละเอียดในหัวข้อ "สิ่งที่แก้ไปแล้ว" แต่ **ยังไม่เคยทดสอบกับข้อมูล Shopee จริง** ทุกอย่างทดสอบกับเว็บ Shopee จำลองใน `test/mock-shopee.js` เท่านั้น

### ขั้นตอนต่อไป (ทำบนเครื่องผู้ใช้ และต้องใช้ Claude in Chrome)

1. `npm install` แล้ว `npm run build`
2. เปิดแท็บ shopee.co.th ที่ login ไว้แล้ว ไปที่หน้า "การซื้อของฉัน" (`/user/purchase/`)
3. ดูว่า Shopee เรียก API อะไรจริงๆ เช่น path, พารามิเตอร์ `list_type`, ขนาดหน้า, `next_offset` และหน้าตาของ JSON ที่ได้กลับมา
4. รันโค้ดใน `web/dist/bookmarklet.min.js` บนหน้านั้น แล้วเทียบผลกับสิ่งที่เห็นบนหน้า Shopee: จำนวนออเดอร์, สถานะยกเลิก, รายการสินค้า, วันที่, วิธีจ่าย และบัตร
5. แก้ `core.js` (ส่วนแปลงข้อมูล) และ `web/bookmarklet.js` (ส่วนที่ดึงข้อมูล) ให้ตรงกับข้อมูลจริง
6. ปรับ `test/mock-shopee.js` ให้หน้าตาข้อมูลเหมือนของจริง ใช้ค่าสมมติ ห้ามใช้ข้อมูลจริงของผู้ใช้ แล้วรัน `npm test` ให้ผ่าน
7. รัน `npm run build` แล้ว commit ลง branch `claude/ecstatic-bardeen-h4wy1a`

### กฎเรื่องข้อมูลส่วนตัว

- ห้ามส่งข้อมูลออเดอร์, ชื่อ, ที่อยู่, เบอร์โทร หรือ cookie ของผู้ใช้ไปที่ไหน และห้าม commit ข้อมูลเหล่านี้
- ห้าม commit โฟลเดอร์ `output/` และ `.shopee-profile/` (มี `.gitignore` กันไว้แล้ว)
- ตัวอย่างข้อมูลใน test ต้องเป็นค่าสมมติเท่านั้น

## โครงสร้างไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `core.js` | ส่วนที่ใช้ร่วมกันทั้งบุ๊กมาร์กและโปรแกรม CLI ห้ามพึ่ง Node หรือ DOM ประกอบด้วย `ordersFromList`, `listPage`, `parseOrder`, `groupOrders`, `buildOutputs` (HTML + CSV), `redact` / `redactPageText` (สร้างไฟล์ตรวจปัญหาที่ตัดข้อมูลส่วนตัวออกแล้ว) |
| `web/bookmarklet.js` | โค้ดที่รันบน shopee.co.th: UI (shadow DOM), การเรียก API, ทางสำรองด้วย iframe, cache ใน localStorage (`shopeeOrderReport.v2`), หน้าผลลัพธ์ และปุ่มดาวน์โหลด |
| `web/page.html` | หน้าเว็บแจกบุ๊กมาร์ก (ตัว placeholder `"__BOOKMARKLET_CODE__"` จะถูกแทนตอน build) |
| `web/build.js` | รวม core + bookmarklet แล้ว minify ด้วย terser ได้ไฟล์ `web/dist/bookmarklet.min.js` และ `web/dist/index.html` |
| `shopee-report.js` | โปรแกรม CLI (Playwright) ใช้ทางเดียวกันอีกทาง: เปิดเบราว์เซอร์ให้ login แล้วดักจับ API |
| `test/mock-shopee.js` | เว็บ Shopee จำลอง มีโหมด `strict` ที่ API ไม่ยอมตอบคำขอที่ไม่ได้มาจากหน้าเว็บเอง จำกัดหน้าละ 5 รายการ และมีออเดอร์ที่ยังไม่จ่าย |
| `test/bookmarklet.test.js`, `test/e2e.test.js` | ทดสอบบุ๊กมาร์ก (ทั้งโหมดปกติและ strict) และทดสอบ CLI |

## วิธีที่บุ๊กมาร์กดึงข้อมูล

1. ดึงรายการ "ยกเลิก" (`get_order_list?list_type=4`) และ "ยังไม่ชำระ" (`list_type=9`) มาก่อน เพื่อทำเครื่องหมายออเดอร์เหล่านี้
2. ไล่ดึงรายการ "ทั้งหมด" จาก `get_all_order_and_checkout_list` (ถ้าใช้ไม่ได้จะลอง `get_order_list?list_type=5`) โดยเลื่อน offset ตามจำนวนการ์ดที่ได้จริงหรือตาม `next_offset` และหยุดเมื่อไม่มีการ์ดเหลือ, `next_offset` เป็น -1 หรือเจอหน้าที่ไม่มีออเดอร์ใหม่ 3 หน้าติดกัน
3. ดึงรายละเอียดแต่ละออเดอร์จาก `get_order_detail?order_id=` ถ้าในข้อมูลไม่มีวิธีจ่าย, บัตร หรือวันที่ จะเปิดหน้าออเดอร์ใน iframe ที่ซ่อนไว้ แล้วอ่านข้อความบนหน้าแทน
4. ถ้า Shopee ไม่ยอมให้เรียก API ตรงๆ (กลไกกันบอต) จะเปิดหน้าของ Shopee เองใน iframe แล้วดัก XHR/fetch ที่หน้านั้นเรียก

**ข้อสันนิษฐานที่ยังไม่ได้ยืนยันกับของจริง:**

- ค่า `list_type`: 3 = สำเร็จ, 4 = ยกเลิก, 5 = ทั้งหมด, 7 = ที่ต้องจัดส่ง, 8 = ที่ต้องได้รับ, 9 = ที่ต้องชำระ, 12 = คืนเงิน/คืนสินค้า
- ราคาในข้อมูลเป็น บาท × 100000
- ชื่อ field ต่างๆ เช่น `info_card.order_list_cards[].product_info.item_groups[].items[]` (`name`, `model_name`, `amount`, `item_price`), `final_total`, `checkout_id`, `status.*.text` (เช่น `label_order_cancelled`) และตำแหน่งของวิธีจ่ายกับวันที่ในข้อมูลรายละเอียด
- ข้อความบนหน้าออเดอร์: "วิธีการชำระเงิน", "เวลาที่สั่งซื้อ" (รูปแบบ dd-mm-yyyy HH:MM) และ "ยอดคำสั่งซื้อทั้งหมด"

## สิ่งที่แก้ไปแล้วในเวอร์ชัน 2

- เลื่อนหน้าตามจำนวนการ์ดที่ได้จริง (เดิมถือว่าได้หน้าละ 10 เสมอ ทำให้ข้ามรายการ)
- ไม่หยุดดึงเมื่อเจอหน้าที่มีแต่ checkout ที่ยังไม่จ่าย
- ดึงสถานะจากการ์ดในรายการ และจากแท็บยกเลิก/ยังไม่ชำระ แล้วตัดออกจากรายงานและยอดรวม
- เลิกเดาวันที่จาก timestamp ที่เก่าที่สุดในข้อมูล (เคยหยิบวันที่ที่ไม่เกี่ยวข้อง ทำให้หยุดดึงเร็วเกินไป)
- ใช้รายการสินค้าจากการ์ดในรายการ ถ้ามีมากกว่าในข้อมูลรายละเอียด
- เพิ่มปุ่ม "ดาวน์โหลดไฟล์ตรวจปัญหา" ที่ตัดข้อมูลส่วนตัวออกแล้ว
