# Tesla Second Screen

ใช้จอกลางของ Tesla เป็น "จอที่สอง" ของโน้ตบุ๊กตอนนั่งทำงานในรถ

หน้าเว็บเดียว เปิดได้ทั้งสองฝั่ง:

```
https://peeangry.github.io/ev-active-sound/screen/
```

- เปิดในเบราว์เซอร์ของรถ → กด **จอ Tesla — รับภาพ** (หรือเข้าตรงที่ `…/screen/#tesla`)
- เปิดบนโน้ตบุ๊ก → กด **โน้ตบุ๊ก — ส่งภาพ** (หรือ `…/screen/#pc`)

จอรถจะขึ้นรหัส 5 หลัก เอาไปกรอกที่โน้ตบุ๊กแล้วกด "เริ่มแชร์จอ" — จบ

---

## มันทำงานยังไง

โน้ตบุ๊กแคปหน้าจอด้วย `getDisplayMedia()` แล้วส่งเป็นวิดีโอ **WebRTC ต่อตรง**
ไปยังเบราว์เซอร์ในรถ ตัวภาพไม่วิ่งผ่านเซิร์ฟเวอร์ใคร — เซิร์ฟเวอร์กลาง
(PeerJS public broker) ถูกใช้แค่ตอนจับคู่รหัสเพื่อแลก SDP/ICE เท่านั้น

ถ้ารถกับโน้ตบุ๊กอยู่ Wi-Fi เดียวกัน ภาพจะวิ่งในวง LAN ล้วน ๆ
หน่วงประมาณ 80–200 ms

## ข้อจำกัดที่ต้องรู้ก่อน (ตรงไปตรงมา)

| เรื่อง | ความจริง |
|---|---|
| เป็นจอที่สองจริงไหม | โดยตัวมันเองคือ **การมิเรอร์ภาพ** ระบบปฏิบัติการยังไม่เห็นว่ามีจอเพิ่ม ถ้าอยากลากหน้าต่างข้ามไปได้จริงต้องใช้ virtual display driver (ดูหัวข้อล่าง) |
| แตะจอรถแล้วคุมคอมได้ไหม | **ไม่ได้** เบราว์เซอร์ส่งอินพุตกลับไปสั่งคอมไม่ได้ ต้องมีโปรแกรมฝั่งคอมคอยรับ ซึ่งอยู่นอกขอบเขตของหน้าเว็บ — จอรถเป็นจอ "อ่านอย่างเดียว" |
| ตัวหนังสือเล็ก ๆ อ่านออกไหม | อ่านออกถ้าตั้งค่าถูก: 5 fps + บิตเรตสูง ๆ จะคมกว่า 30 fps มาก โค้ดตั้ง `contentHint` และ `degradationPreference: maintain-resolution` ให้แล้ว แต่ก็ยังสู้สาย HDMI ไม่ได้ |
| ใช้ตอนขับได้ไหม | **ไม่ควรและส่วนใหญ่ทำไม่ได้** — เบราว์เซอร์ Tesla ถูกจำกัดตอนรถเคลื่อนที่ ออกแบบมาให้ใช้ตอนจอด/ชาร์จ |
| รถอยู่ LTE คนละเน็ตกับคอมได้ไหม | ได้เฉพาะเมื่อ NAT ยอมให้ต่อตรง ถ้าไม่ยอมต้องมี **TURN server ของตัวเอง** (ใส่ได้ในหน้า "ตั้งค่าขั้นสูง") ซึ่งจะกินแบนด์วิดท์ของทั้งสองฝั่ง |
| เบราว์เซอร์ในรถรองรับ WebRTC แน่ไหม | **อันนี้คือจุดที่ต้องลองจริง** Chromium ในรถแต่ละรุ่น/แต่ละเวอร์ชันซอฟต์แวร์ไม่เท่ากัน — กด "ตรวจเบราว์เซอร์" บนจอรถก่อน ถ้าไม่ผ่าน ใช้ทางสำรอง MJPEG ด้านล่าง |
| จอรถหรี่/ดับเองไหม | อาจหรี่ได้ โค้ดขอ Wake Lock ให้แล้วถ้าเบราว์เซอร์รองรับ |

## ทำให้เป็น "จอที่สองจริง ๆ"

ต้องหลอกให้ระบบปฏิบัติการเชื่อว่ามีจอเพิ่มมาหนึ่งจอ แล้วค่อยแชร์จอเสมือนนั้นมา:

- **Windows** — [Virtual Display Driver](https://github.com/itsmikethetech/Virtual-Display-Driver)
  (IddSampleDriver) สร้างจอเสมือนได้ ตั้งความละเอียดให้ตรงกับพื้นที่เบราว์เซอร์ของรถ
  แล้วใน Windows Settings → Display เลือก "Extend"
- **macOS** — [BetterDisplay](https://github.com/waydabber/BetterDisplay) สร้าง dummy display
- **Linux** — เพิ่ม virtual output ด้วย `xrandr --newmode/--addmode`
  (X11) หรือ headless output ของ compositor นั้น ๆ (Wayland)
- อีกทางที่ง่ายกว่าและไม่ต้องลงไดรเวอร์: ซื้อ **HDMI dummy plug** (headless ghost adapter)
  เสียบทิ้งไว้ ระบบจะเห็นเป็นจอจริงเลย

จากนั้นตอนกด "เริ่มแชร์จอ" ให้เลือกจอเสมือนตัวนั้น — ลากหน้าต่างข้ามไปได้ตามปกติ

## ปรับให้ภาพดี

| อาการ | แก้ |
|---|---|
| ตัวหนังสือเบลอ/เละ | เฟรมเรต **5 fps** + บิตเรต 8–12 Mbps |
| ภาพกระตุก หน่วงสะสม | ลดความละเอียดเป็น 1280, ลดบิตเรต |
| ต่อไม่ติดเลย | เอารถเข้า Wi-Fi/hotspot เดียวกับโน้ตบุ๊ก |
| ต่อติดแต่ภาพไม่ขึ้น | เปลี่ยน codec เป็น H264 (หรือ VP8) — Chromium เก่าบางตัวถอด VP9 ไม่ได้ |
| ช่อง "เส้นทาง" ขึ้น TURN relay | แปลว่าไม่ได้ต่อตรง คุณภาพจะตกและเปลืองเน็ต — ย้ายมาวง LAN เดียวกัน |

ช่อง **สถานะการส่ง** บนโน้ตบุ๊กบอกทั้งบิตเรตจริง เฟรมเรตจริง RTT
และเหตุผลที่คุณภาพถูกลด (`qualityLimitationReason`) ใช้ไล่ปัญหาได้ตรงจุด

## ทางสำรองเมื่อเบราว์เซอร์รถไม่รองรับ WebRTC

`tools/lan-mirror.py` แคปจอเองแล้วเสิร์ฟเป็น MJPEG ผ่าน HTTP ธรรมดา
เบราว์เซอร์รุ่นไหนก็เปิดได้ ขอแค่แสดง `<img>` เป็น:

```bash
pip install mss pillow
python3 tools/lan-mirror.py            # จอหลัก
python3 tools/lan-mirror.py --monitor 2 --fps 5 --quality 85   # จอเสมือน อ่านเอกสาร
```

สคริปต์จะพิมพ์ URL แบบ `http://192.168.x.x:8080/` ออกมา เอาไปเปิดในรถ

ข้อแลกเปลี่ยน: MJPEG ไม่บีบอัดข้ามเฟรม กินแบนด์วิดท์กว่ามาก และไม่มีการเข้ารหัส
— ใช้เฉพาะในวง Wi-Fi ที่ไว้ใจได้เท่านั้น

## ตั้ง signaling / TURN ของตัวเอง

ค่าเริ่มต้นใช้ PeerJS public broker ซึ่งฟรีแต่ไม่การันตี uptime
ถ้าจะใช้จริงจังให้รัน [PeerServer](https://github.com/peers/peerjs-server) เอง
แล้วใส่ host ในหน้า "ตั้งค่าขั้นสูง" **ทั้งสองฝั่ง**
(ฝั่งรถตั้งได้จากหน้า "ตรวจเบราว์เซอร์" → ตั้งค่าขั้นสูง) ค่าจะถูกจำไว้ใน
localStorage ของเครื่องนั้น ๆ

TURN server เอาไว้ใช้ตอนรถกับคอมอยู่คนละเน็ต — ตั้ง
[coturn](https://github.com/coturn/coturn) เองได้ ใส่ url/user/pass ให้ตรงกันทั้งสองฝั่ง

## เคล็ดลับ

- เก็บ `…/screen/#tesla` เป็น **bookmark ในรถ** ครั้งหน้าแตะทีเดียวจบ
  (พิมพ์ URL ยาว ๆ บนจอรถทรมานมาก)
- รหัสจะเปลี่ยนทุกครั้งที่รีเฟรชหน้าในรถ ถ้ากรอกแล้วขึ้น "ไม่พบรหัสนี้"
  ให้ดูตัวเลขบนจอรถใหม่
- ปุ่ม `+` / `−` บนจอรถซูมเข้าไปดูมุมใดมุมหนึ่งของจอคอมได้ ลากเพื่อเลื่อน
  — ช่วยมากตอนอ่านโค้ดจากที่นั่งคนขับ
